## 当前实现

- 现有记录统一升级为当前可编辑结构：人员履职√转正常，字符串问题转为逐条文字及图片对象；旧项目部自由说明作为其他保留原文与附件，不根据关键词臆测检查结论。升级前按日期保留原记录备份，有有效编辑锁时延后重试；未保存内容不因升级变成已保存，项目部用户关联缺失时编辑保存前选择有效人员；调度人员选填，可清空后保存。2026年10月24、25、26、27日作为完整评审示例，包含当日全部项目的统一调度、值班人员及项目经理内容和模拟图片，覆盖正常、发现问题、其他及三个填写部分结论不同的情况；替换前备份原记录，仅执行一次，后续刷新不覆盖人工修改。 本地备份存放于IndexedDB的meta中，键为before-current-format:日期；示例填充标记为full-review-v1:日期。

- 每日检查固定日期＋五类结果，两个入口固定显示“统一调度检查填写”“项目部检查填写”，保留查看详情；无日期卡片、每日选列或数值合计。两页签均默认含当天向前30日（当天减29天至当天），各自日期/分页独立；空日期点击查询为不限，重置恢复默认。列表10/20/50、真实总数、翻/跳页，查询或改条数回首页、超界修正。检查总表十个明细字段＋固定眼睛查看详情操作，两类合计按完整筛选范围；临时列设置不含操作列，切入或刷新恢复默认。
- 下级返回通过来源Route Query恢复日期（含不限）、页码、条数、页签及可恢复滚动，重新读取最新摘要；总表实际详情入口同样恢复。页面返回和浏览器后退一致，恢复后消费来源参数，菜单新进入或页面刷新按默认初始化，不永久记忆。
- 统一调度仍为基本信息、全项目检查表和整体备注，项目抽屉两个Tab，项目部内容只读。详情标题/面包屑为COC调度会检查记录表详情，完整关联只读，不放填写/范围操作。行点击保留，按钮不重复触发，操作列仅填写（编辑态）/查看详情（只读态）及适用删除。
- 项目部入口仅检查情况项目列表，保留项目名称、两类姓名/结果/截图与填写操作，上方显示总数和两类已填数；无基本信息、整体备注、HQ检查列、项目单选区或删除。添加仍用既有ensureProject补共享行。列表每页10项、支持10/20/50，进入/开始填写/保存/关闭抽屉后恢复有效分页。项目部抽屉无Tab、无当日统一调度字段，两类分组可独立折叠，开始填写或校验报错时展开，标题显示当前状态、正文不重复标签，值班/经理各组独立持锁、编辑、保存和取消；保存一组保留另一组输入，关闭未保存内容先确认。不增加批量保存。
- 统一调度/完整详情在日期下、Tab外显示调度标记，HQ编辑只有勾选框、无附加纳入文字，详情只读是/否；项目部移除调度字段和Tab。折叠不清空输入或释放有效锁，编辑标题状态随草稿同步；收紧顶部信息行与Tab/首组的间距。应用仍只改草稿，页面保存才保存。项目抽屉、正文及表单沿用14px层级，不再依赖body16px。
- 空字段统一两个短横杠“--”，其他状态浅灰info标签配实际说明；保留正常/发现问题原标签。DailyCheckContent摘要预览前两条问题，日表检查/截图列改用DailyCheckImages紧凑可点击缩略图，不显示图片N张；图片点击只预览，完整抽屉保留所有问题及原附件归属。daily-dispatch-theme.css只将本模块表格悬停改主题浅色，与表头区分，含固定列，不影响其他模块。
- 新日默认取创建时未隐藏项目；历史按保存项目ID/名称快照及内容查询，包括现在隐藏的空白行。范围外新增限制当前未隐藏，共享关系按ID增补/恢复，HQ保存显式增删合并，不用旧数组覆盖新补行。删除按最新记录再保护，仅未人工修改、未保存的初始行可确认移除，已有保存/调度标记/附件不可清空后绕过。
- 标签与隐藏分开；prepareHq原子记录一次默认快照，未保存编辑副本带出勾选/正常和参会，取消重进沿用，后续勾选不补值、旧保存不回填。正式首次重校范围等既有差异仍见符合性核对，不因本次UI修订视为已实现。
- 人员履职正常/其他；其他100字。安全/质量/摄像头和项目部发现问题每字段/部分1～10条，每条有效描述最多500字、图片必填1～9张、单张5MB，逐条校验，不借用别条或另一部分图片。项目部正常说明和1～9张截图、其他说明最多500字和1～9张截图仍必填；HQ正常/其他不新增截图输入，项目备注仍选填0～9张。历史缺图保留读取，重新保存所属部分时按新规则校验，未改问题也不能跳过。问题数量计算仍按有效文字，不改历史统计。
- 会话内切换分支临时保留，保存只提取当前生效分支；取消不保存临时输入。项目备注100字、整体备注500字，旧导出说明从业务区移除但存量原文保留。
- 实际操作人由Web登录启用用户解析，未关联不借用其他ID。三个候选复用系统姓名（组织-岗位）展示，选中/保存仍为ID和姓名快照。调度人员选填，留空保存同时清空ID/姓名，选择时仍须安质部启用用户，无框下历史姓名。项目部两类新填写均默认实际登录启用用户，编辑保留原业务姓名；项目默认候选补入合法已选用户，回显与保存允许跨项目启用用户。GAP-04已对齐，关键词全系统搜索仍为GAP-05；不把默认候选改成全系统。
- 五类状态独立：HQ三类仅已保存勾选项目，值班/经理各取当日全部已纳入项目。数值只取HQ范围安全＋质量、独立摄像头，项目部问题不并入；有有效问题计条数，无问题且明确正常为0，无结论/仅其他为“--”；范围合计只累加有效数，全空为“--”。0不代表全部已填。

## 数据与替换接口

`src/mock/dailyDispatchCheck.js`继续使用既有IndexedDB数据库及days/locks/logs/meta对象仓库，没有清库或覆盖式版本升级。

- 每天一条主记录，`hq.rows`保留轻量项目快照；新行仅项目ID、名称、调度标记，不为每天每项目预建三份空检查正文。
- 统一调度字段与`people[项目ID].duty/manager`分别保存，汇总仅按日期+项目ID读取。`submit`的白名单拒绝越界字段回写，项目部姓名由有效用户ID重新解析。
- 统一调度范围变更通过`scopeChanges.addedIds/removedIds`合并；移除的空白关系保留在`removedRows`供恢复名称快照。`ensureProject`补行幂等，不计业务更新时间。
- `prepareHq`仅写首次配置元数据；`hqDraftForEditing`生成未保存编辑副本；`hqPayload`排除只读人员字段和界面标记；`activeCheck`排除未激活分支。
- 统一调度按日期+区域锁，项目部按日期+项目ID+部分锁。事务中检查锁令牌、所有者、期限、独立版本，成功保存及日志后释放。共享行同事务核验，防止不同部分覆盖。
- 标签为`airport-project-dispatch-tags-v1`的localStorage布尔配置；旧`airport-inspection-columns-v4:<用户ID>`列偏好已不再被本模块读取，当前仅总表内存临时选列。跨标签页保存通过现有BroadcastChannel通知，只读数据刷新不会重置当前编辑内容。

## 存量与技术边界

- 现有记录按当前结构升级后可编辑：√转正常、字符串问题转对象、自由说明与附件放入其他分支；原记录备份于meta，编辑锁未释放时延后；升级不把未保存默认值变为有效结果。指定四天完整示例只填充一次，后续人工修改保留。
- 现有系统用户与项目数据本身为模拟源；当前登录账号必须能映射启用系统用户才默认姓名，无映射时留空，不借用其他账号。项目关系缺失时默认列表仍提示维护；合法已选跨项目用户可回显，安质部无候选也可留空保存。真实全系统搜索及人员服务尚待接入。
- 图片仍以data URL存于本浏览器。90张小图的数量与关联可验证，不代表真实450MB附件在所有浏览器都可保存；实际容量由浏览器配额决定。事务失败不报告成功，保留编辑副本；后端应提供对象存储、配额、上传重试及可信审计。
- 模拟编辑锁只覆盖同浏览器同源，不能证明跨用户/设备权限和并发安全。生产权限、服务端时间、定时生成、可靠锁及审计仍需真实后端实现。
- 首次v4打开只对缺失日期补充明确的30天评审记录，不替换已有记录。另一次性补充最多8组标明场景的演示表单，覆盖正常、多问题图片、其他、部分填写、项目部独立保存、非调度问题排除、零调度及多项目人员；已有保存、初始化元数据、人员正文、内容或有效锁的日期一律跳过。浏览器关闭时不存在服务端自动生成任务。
