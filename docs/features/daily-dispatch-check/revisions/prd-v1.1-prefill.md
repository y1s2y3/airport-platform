# 每日调度检查 v1.1 项目范围与临时预填修订

所属系统：工程建设智慧管控一体化平台

当前业务依据为用户更新后的同版[Word PRD v1.1（项目范围与预填修订）](../requirements/Daily_Dispatch_Check_PRD_v1.1_project_scope_revision.docx)。同版旧稿与v1.0保留查阅，不能替代本次更新。源文件未改写；下载副本与用户最后提供的文件逐字节相同。

## PRD核对与行为边界

最新修订与本次要求一致。5.2、7.2.4、7.2.7、AC-02-04/06进一步明确：项目范围在日表生成时根据当时隐藏配置形成；之后上游隐藏配置变化不自动增删，进入填写或重新读取标签不重新生成列表。预填只作用于已纳入该日期范围且当前未隐藏的项目。用户主动添加沿用当前未隐藏、未纳入和内容保护等既有规则。

7.2.7及AC-02-07/08要求：同一日期统一调度首次成功保存前，每次取得占用进入均读取最新配置，形成会话草稿；确认放弃后完全丢弃，继续填写保留草稿；成功保存后再进入以已保存内容为准，不因标签变化、手动勾选、添加项目或清空后再保存补正常。项目部值班和经理的独立保存不决定统一调度的首次保存状态。

PRD正文仍混用“检查统计表”和“检查统计”；本次按用户明确要求及7.5概述，将界面页签、隐藏路由标题及说明统一为“检查统计”，保留原路由与query标识以兼容书签、返回和分页。其他PRD缺口不因文档替换而擅自扩改。

## 相关函数与修改前后

| 函数或位置 | 修改前 | 修改后 |
| --- | --- | --- |
| prepareHq（src/mock/dailyDispatchCheck.js） | 首次进入把标签命中写入日记录dispatchDefaults；以后跳过重新读取。 | 先验证占用和统一调度自身保存状态；未保存时每次重新读取可见范围与标签，按“已纳入且当前未隐藏”过滤，仅返回本次临时hqPrefillProjectIds，不写入日表。 |
| hqHasBeenSaved（src/utils/dailyDispatchCheckRules.js） | 没有统一的首存判断函数。 | 仅依据统一调度自身version>0或firstSubmittedAt，兼容已有成功保存记录；不使用曾进入、曾初始化或项目部保存状态。 |
| hqDraftForEditing（同上） | 依据持久化dispatchDefaults补正常。 | 只消费本次临时输入并克隆草稿；旧缓存不能恢复预填；已保存部分不预填。原有表头默认值及非空内容保护保留。 |
| 旧dispatchDefaults兼容（prepareHq） | 放弃后缓存仍可恢复上次标签。 | 仅对未成功保存日表移除旧缓存，保留业务正文、项目关系、人员、保存时间与日志；已保存数据保留。旧固定演示日期沿用既有示例完成标记，防止清理缓存后示例生成器伪造一次成功保存，该标记不参与业务首存判断。 |
| startHq、submitHq、cancelHq、抽屉应用与退出确认 | 既有页面进入、占用、保存及取消链路。 | 保持原实现；不增加抽屉动作的初始化调用。成功保存仍由原有事务设置版本与firstSubmittedAt；校验、保存或占用失败不改变成功状态。 |
| dailyDispatchDocuments与DailyPrototypeNote | 下载上一份Word，未清楚区分固定范围和预填。 | 下载最新同版v1.1二进制；说明明确固定范围、临时预填及成功保存边界。 |

构建产物中的Czt等短名会随打包变化。本次修改实际源码并重新构建HTML，没有手工修改压缩符号。既有保存事务、项目部保存、统计、校验和页面CSS均保留。
