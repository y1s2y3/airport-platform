# 每日调度检查：抽屉填写与折叠调整

根据本会话的三张截图及四点要求修订，承接1103汇报调整。以[PRD V1.5](../requirements/每日调度检查需求文档_PRD.md)为最新业务交底基线，AC-01～54连续编号；该修订覆盖此前“项目部单Tab及只读调度标记”的界面方案。

| 用户要求 | 当前行为 |
| --- | --- |
| 项目部删调度字段和单一页签，增加折叠 | 项目名/日期下直接显示两类人员检查，各自可收起展开。开始填写/编辑或校验报错展开对应组，折叠保留输入、问题、图片与有效编辑占用，不提交、不影响另一组。 |
| 填写时标题显示状态 | HQ履职/安全/质量/摄像头，以及项目部两组标题显示当前草稿的正常/发现问题/其他，统一调度问题条数取有效描述，项目部组标题仅显示状态；未提交不刷新有效台账统计，收起仍显示。项目部只读正文不重复标签。 |
| 调度勾选旁去掉纳入文字 | HQ保留带可访问名称的原勾选框，去掉附加文字；只读详情仍是/否；项目部不显示该字段。未修改调度业务含义或保存范围。 |
| 顶部间距过大 | 收紧日期/调度信息与Tab/首组之间的留白，项目部直接使用内容滚动区；保留顶部固定、窄屏约束及底部操作。 |

仍使用原检查字段、逐问题图文校验、三部分独立保存、编辑锁、范围及历史保护、分页与返回查询状态。没有新增业务字段、改变数据库结构或接入真实后端。逻辑/物理数据库与SQL仅更新PRD引用版本。

验证沿用smoke-inspection-report-1103.mjs，并补充标题状态实时变化、收起再展开输入/图片保留、独立折叠、开始填写自动展开、错误展开、两种顶部间距和重复状态检查。开发/构建实际结果见[实现与验证](../implementation.md)最新修订节。

## 浏览器批注：顶部信息行内边距

检查日期行padding-top由8px改为15px；统一调度行padding-top由4px改为8px、padding-bottom由0改为8px。修改落在本模块抽屉已有上下文样式及调度行覆盖中，不使用临时Element Plus ID或预览标记。填写和只读共用，项目部日期行同步，项目部仍无调度字段/Tab。左右内边距维持桌面20px、480px及以下16px，不新增仅针对1413×871的断点。

## 项目部日期行下留白补充

按项目部填写页的浏览器批注，为该入口的日期行增加5px下内边距。通过入口条件绑定语义类daily-drawer-project-date，限定项目部填写抽屉；统一调度与完整详情日期行下边距沿用0px。共享上边距15px、调度行上下8px和原20/16px响应式左右边距继续生效，不使用临时预览ID，不新增断点。
