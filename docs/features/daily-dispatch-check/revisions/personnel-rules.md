# 每日调度检查：人员选填与默认值修订

> 来源：独立功能工程提交 eaebc312df99f0a75f6b59f4fd97f0469dd15a83 的实现/迭代记录；仅适配工程目录和资料引用。本文原有日期验证属于来源工程，本次团队工程合入结果见[集成验证记录](../integration.md)。未随代码迁移的历史资料保留来源标识。


本轮按用户最新确认修改，业务基线为[PRD V1.6](../requirements/每日调度检查需求文档_PRD.md)。不增加入口、审批或数据结构；历史评审记录保留其当时口径。

## 1. 安质部调度人员选填

- 取消必填星号，填写提示为“请选择人员（选填）”。未选择也能提交统一调度，包含旧记录只有姓名而未关联用户的情况。
- 有选择时仍只能使用安质部及下级部门的启用系统用户；不能用手填姓名、停用账号或其他部门账号绕过校验。
- 清空或未选择的成功提交同时清除调度人员ID和姓名，避免空选择框仍保存旧姓名。只读、取消或失败不修改原记录。
- 原型用空字符串保存空ID；正式数据库使用NULL ID、空字符串姓名、needs_user_binding=0。历史迁移姓名只在未重提交的原记录中保留。

## 2. 项目部两类姓名默认值

- 值班人员检查、项目经理检查的新填写都自动带出实际登录的启用系统用户，不默认项目信息管理中的项目经理。
- 当前用户不属于当前项目时，也能正常回显和提交；用户可在原控件中改选。默认带出不等于提交，不提前改变已填数或业务更新时间。
- 编辑已有提交时保留该次保存的业务姓名，不因操作账号变化而覆盖。无有效启用用户映射则留空，不能借用其他用户身份。
- 两类姓名仍为必填，关联有效启用用户ID；实际操作账号独立记录。两个部分仍独立持锁、独立保存，提交其中一个不覆盖另一个草稿或统一调度内容。
- 默认候选仍为当前项目启用账号，合法已选用户额外补入供回显；本轮没有将默认列表扩成全系统。关键词全系统搜索仍属于[GAP-05](../requirements/每日调度检查原型符合性核对.md)，不宣称已完成。

## 3. 数据与文档

复用inspectionPersonnel、DailyUserPicker、现有表单和仓储submit。调度空值在载荷与仓储两层归一，项目默认候选与合法已选用户范围分开处理。未改检查内容、图片、统计、历史项目范围、日期查询或返回状态规则，未接入真实后端。

PRD、原型符合性、两份原型说明、弹窗说明/下载清单、实现与架构、逻辑/物理数据库设计及SQL注释同步；12张表、139个字段、25个非主键索引结构保持一致。数据库字段原本允许空值，本轮不新增迁移或执行SQL。
