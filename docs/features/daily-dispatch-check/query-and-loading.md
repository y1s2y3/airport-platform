## 当前交互

- 【每日检查】【检查总表】初次进入、菜单新进入、页面刷新及重置均为最近30个自然日（含当天），起日=当天减29天、止日=当天；“近一个月”也统一采用此30日口径。两个页签分别保留本次手动查询状态。日期修改和清空都点击原有【查询】后应用，不新增自动查询；空日期表示不限制日期，完整范围包含两端，部分缺失/无效范围才提示补齐。
- 两页签各自保留日期与分页。列表默认10条，可切10/20/50，支持上一页、下一页、页码和跳页；真实总数，查询/改条数回首页，超界修正。日期不限也只渲染当前页，空白日表仍在结果中，空字段不改成0；总表合计取完整匹配范围。
- 从每日列表进入统一调度、项目部填写或详情，或从检查总表进入详情后返回，保留离开前的日期（包括不限）、页码、条数和页签，条件允许时恢复表内横纵滚动；重新读取最新摘要，再恢复有效旧页码。普通刷新沿用现有回首页行为。
- 统一调度取得同日独占后进入；占用失败提示并回每日检查台账。顶部返回和底部取消先弹【未保存内容】，确认放弃才释放并返回；保存成功直接回台账，均恢复来源日期（含不限）、条数及有效页码，并读取最新摘要。项目部组内保存/取消仍只处理本组。
- 来源状态保存在Vue Router查询参数，独立于检查数据。进入下级前替换原台账历史项并带returnTo，页面返回和浏览器后退一致；ledgerState缺失表示默认初始化，dailyRange=all明确表示不限。返回恢复后消费来源参数，页面刷新或从菜单地址新进入仍用默认条件；不用localStorage/sessionStorage永久记忆。
- 总表保留只读，固定眼睛图标＋查看详情入口；打开与每日检查相同的日表详情，实际返回恢复总表来源状态，不提供填写入口。列设置仍只在当前页面临时生效，切入或刷新总表恢复默认列。

## 原型的数据读取

| 位置 | 方法与行为 |
| --- | --- |
| 台账 | `listLedgerSummaries()`继续使用既有IndexedDB仓储，逐日游标投影摘要，按唯一日期键倒序返回。复用原统计和五类状态函数，不用完整问题、people正文或图片URL作为页面列表数据。 |
| 日期筛选与分页 | 在本地摘要集合上筛选，再复用`BusinessPagedTable`按页截取；清空、选日期和翻页都不会为查询新增网络请求或人造延迟。 |
| 某日详情/填写 | 沿用`getDay(date)`按日期读完整日表；项目范围与名称取保存快照，当前隐藏状态不筛掉历史项目及未填行。 |
| 刷新/保存通知 | 最新读取序号保护成功、失败和loading；失败明确提示并可刷新重试，不用0条掩盖失败。成功保存仍触发原通知，详情合并关联数据时保留未保存编辑。 |
| 项目部检查 | 日期页展示当日范围及两类检查摘要，复用项目表分页。按项目打开无页签项目部抽屉；开始填写、保存通知及关闭不重置原有效项目页码/条数，两部分仍独立保存。 |
| 附件 | 继续使用本地data URL及原有预览，不模拟文件服务。日期台账摘要不携带图片；日表检查列及截图列使用可预览缩略图，详情保留问题与图片归属。 |

这是**前端分页**。本地仓储仍会扫描存量日表；既有ensure首读/兼容检查仍可能读取完整记录。由于图片内嵌在本地记录中，摘要投影不意味着IndexedDB已经物理拆表、按页磁盘读取或提供真实按需文件服务。本轮没有改数据库版本、清库、重建历史项目关系或改变三部分独立保存。

代码主要位于`dailyDispatchLedgerQuery.js`、`useDailyDispatchLedger.js`、`dailyDispatchLedgerNavigation.js`和既有仓储/页面。调度壳缓存同一个loader对应的异步组件定义，避免只改查询参数就重挂载页面；共用分页只新增获取/恢复分页与滚动的方法，其他表格默认行为不变。

## 正式开发建议：服务端分页

以下为**拟议契约**，不是已存在的HTTP服务，最终名称遵循正式系统规范。

### 列表摘要查询

建议`GET /daily-dispatch-check/records`，服务端先按真实登录权限和其他条件筛选，再排序、分页；不能为了当前10条先下载全部历史表单。

| 参数 | 约束 |
| --- | --- |
| startCheckDate / endCheckDate | 可选，YYYY-MM-DD业务日期，含首尾；不限时省略，不自动填最近30天。页面完整范围成对保存，若未来接口支持单边边界需按正式规范处理。 |
| pageNo / pageSize | 从1开始，pageSize支持10/20/50；筛选或条数变化请求第1页，返回恢复时请求原有效页。 |
| 其他已有筛选条件 | 原样传递，清空日期不清掉其他条件，不新增本轮未有的筛选控件。 |
| sort | 如需显式传递，检查日期倒序、唯一recordId倒序等稳定组合；若日期在权限域内唯一，可使用该唯一键。 |

响应至少包含`records`（当前页摘要）、`total`（全量匹配数）；可返回`pageNo/pageSize`。摘要应覆盖两种现有列表实际需要的字段：记录标识、检查日期、已保存表头（含安质部调度人员）、统一调度项目数/名称摘要、五类检查结果、两类有效问题数量、最近更新时间及入口填写标记。未形成数量为null，前端显示“--”，不强制补0。

检查总表的范围合计仍是全部匹配记录的合计，不能只把当前页相加。正式接口可在同一响应提供`totals.safetyQuality/totals.camera`，或另设按相同条件与权限计算的汇总查询；全部无有效数值仍为null，保持既有统计口径。

服务端使用稳定排序和一致的过滤/计数口径，优先保证同一查询快照内翻页不重复/遗漏。若列表在翻页期间被并发增删，需按正式接口能力补充查询快照标识或等效一致性方案；单有次级排序不能承诺任意并发变更下的快照一致性。没有真实后端前，不伪造已实现的快照服务。

### 完整日表与附件

建议`GET /daily-dispatch-check/records/{recordId}`，也可按权限域+检查日期唯一定位。进入查看或填写时查询基本信息、保存项目范围、统一调度、值班人员、项目经理、问题、附件引用及所需版本信息；三部分继续独立保存，不以整个旧表单覆盖其他部分。

附件返回标识、名称、类型/大小和已有缩略图引用；详情显示缩略图，查看原图时再取原图资源。遵守鉴权及资源有效期，继续支持现有预览放大，不改变问题关联。此接口及文件服务当前均未接入。

筛选、翻页和返回都由一份查询状态生成请求；正式异步查询需要取消或忽略旧响应，加载期间显示loading，失败保留可理解错误并允许重试。业务权限必须由服务端执行，日期为空不扩大权限。分页数失效时修正到有效页，不顺带重置筛选。
