# 移动端待办处置策略（已定稿口径）

| 项 | 内容 |
|----|------|
| 版本号 | V1.0 |
| 更新日期 | 2026-08-24 |
| 状态 | 已定稿 |
| 所属系统 | 智慧工程建设管控一体化平台 |
| 模块名称 | 移动巡检 / 个人中心 |

## 1. 背景

Web 端已约定：**个人中心 = 唯一处置台**，业务模块详情只读。移动端需在巡检 App 场景下支持现场办理，并与 Web 个人中心数据口径对齐。

## 2. 处置入口

| 端 | 巡检执行 | 整改 / 复查 / 项目经理审批 | 质量验评审批 | 其他待办（品牌、样板、COC 等） |
|----|----------|---------------------------|--------------|-------------------------------|
| **Web** | 个人中心待办 | 个人中心待办 | 个人中心待办（embed） | 个人中心待办 |
| **移动巡检 App** | **App 内直接办理** | **App 内直接办理** | **App 内直接办理**（与 Web 待办数据一致） | 优先个人中心 Web；App 消息中心可跳转 Web handle |

## 3. 数据对齐

- 移动办理结果须写回与个人中心 Web **同一套 Mock / 后续同一 API**，保证「App 办结 = Web 已办」。
- 路由示例（已实现原型）：`/mobile/tasks/:id/execute`、`/mobile/rectify/:id/execute` 等。

## 4. 与 Web 只读规则的关系

- **Web 业务模块详情**：仍只读 + `PersonalCenterReadonlyHint`。
- **移动 App 对应执行页**：**不**套用 Web 只读提示，允许提交（本策略例外仅适用于上表移动可办类型）。

## 5. 后续实现清单（未在本轮 Web 原型全部落地）

- [ ] 质量验评移动审批页（若独立路由）与个人中心 `qm_inspect` 待办双向同步
- [ ] 移动消息中心待办跳转：App 能办的走 App 页，不能办的 deep link 到 Web `/personal-center/todo/handle`
